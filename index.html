Класи, об'єкти та інкапсуляція

Класи та об'єкти C++

🎙️ Як почати відповідь (База)

"Клас — це креслення або шаблон, за яким створюються об'єкти. Він об'єднує дані (поля) та функції для роботи з ними (методи) в одну сутність. Об'єкт — це конкретний екземпляр цього класу в пам'яті."

🎯 Часті питання викладача

1. Що таке інкапсуляція?
Це приховування внутрішньої реалізації класу від зовнішнього світу. Ми робимо поля private, а доступ до них надаємо через public методи (гетери і сетери).
2. Які є специфікатори доступу?
public: доступно всюди.
private: доступно ТІЛЬКИ методам цього ж класу (за замовчуванням у class).
protected: доступно класу та його спадкоємцям (важливо для успадкування).
3. Що таке конструктор і деструктор?
Конструктор викликається автоматично при створенні об'єкта (виділяє пам'ять, задає початкові значення). Не має типу повернення, ім'я збігається з класом.
Деструктор (з тильдою ~) викликається при знищенні об'єкта. Потрібен для очищення динамічної пам'яті.
ООП / LW1 / C#

Класи та об'єкти C#

🎙️ Як почати відповідь

"Клас у C# — це посилальний тип даних (reference type), який виділяється в купі (heap). Головна відмінність C# від C++ у тому, що тут немає поділу на файли заголовків (.h) та реалізації (.cpp) — усе пишеться в одному файлі. Також C# використовує Властивості (Properties) для зручної інкапсуляції."

🎯 Часті питання викладача

1. Що таке Властивості (Properties) і чим вони кращі за поля?
Властивість — це механізм, який виглядає як звичайне поле, але всередині містить методи get (читання) і set (запис). Це дозволяє контролювати, які дані записуються в об'єкт, не створюючи громіздких методів GetAge() чи SetAge() як у Java або C++.
2. Чи є в C# деструктори і як очищується пам'ять?
У C# пам'яттю керує Збирач сміття (Garbage Collector - GC). Він автоматично видаляє об'єкти, на які більше немає посилань. Тому ручне управління пам'яттю (як delete у C++) не потрібне.

Перевантаження операторів у C++ C++

🎙️ Як почати відповідь (База)

"Перевантаження операторів — це механізм, який дозволяє надати стандартним операторам (+, -, ==) свій власний зміст для об'єктів наших класів. Зручно писати a + b замість a.add(b)."

🎯 Часті питання викладача

1. Які оператори НЕ можна перевантажити?
:: (дозвіл області видимості), . (доступ до поля), .*, ?: (тернарний) та sizeof. Бо це порушить базову логіку доступу мови.
2. Різниця: метод класу чи дружня функція (friend)?
Метод: Лівий операнд ЗАВЖДИ є об'єктом нашого класу (неявно це this). Добре для +=, =.
friend: Використовуємо, коли лівий операнд — це ІНШИЙ тип. Наприклад << (зліва std::ostream). Має доступ до private полів класу.
ООП / LW2 / C#

Перевантаження операторів C#

🎙️ Як почати відповідь

"У C# перевантаження операторів дозволяє нам визначити поведінку стандартних математичних чи логічних операцій для наших класів. Але синтаксис суворіший, ніж у C++: оператор обов'язково має бути public static."

🎯 Часті питання викладача

1. Чому оператор у C# обов'язково `public static`?
Тому що оператор застосовується до типів (класів), а не до конкретного екземпляра об'єкта. Він не має вказівника this. public потрібен, щоб оператор був доступний звідусіль.
2. Чи можна в C# перевантажити оператори `==` або `!=`?
Так, але є правило: вони перевантажуються тільки парами. Якщо ви перевантажили ==, компілятор змусить вас перевантажити і !=. Те саме стосується > та <. Крім того, рекомендується перевизначити методи Equals() та GetHashCode().
3. Чи існують в C# дружні функції (friend) для перевантаження?
Ні, концепції friend у C# не існує через суворішу інкапсуляцію.

💻 Як пояснювати свій код

public class Point {
    public int X { get; set; }
    public int Y { get; set; }

    public Point(int x, int y) { X = x; Y = y; }

    // 1. Пояснення: "Це перевантаження оператора додавання. 
    // Він public static. На вхід приймає два об'єкти нашого класу і повертає НОВИЙ об'єкт."
    public static Point operator +(Point p1, Point p2) {
        return new Point(p1.X + p2.X, p1.Y + p2.Y);
    }
}

Успадкування та Поліморфізм C++

🎙️ Як почати відповідь (База)

"Успадкування дозволяє створити новий клас на базі існуючого, перейнявши його поля та методи. Поліморфізм — це здатність функції обробляти дані різних типів (класів) через спільний інтерфейс базового класу, використовуючи віртуальні функції."

🎯 Часті питання викладача

1. Що робить ключове слово `virtual`? (ДУЖЕ ВАЖЛИВО)
Воно вмикає пізнє (динамічне) зв'язування. Програма вирішує, яку саме функцію викликати, не на етапі компіляції, а під час виконання програми (runtime), залежно від того, на який РЕАЛЬНИЙ об'єкт вказує вказівник базового класу. Для цього створюється віртуальна таблиця (vtable).
2. Що таке абстрактний клас?
Це клас, який містить хоча б одну чисто віртуальную функцію (закінчується на = 0). Неможливо створити об'єкт абстрактного класу. Він слугує лише як інтерфейс для спадкоємців.
3. Навіщо потрібен віртуальний деструктор?
Якщо ми видаляємо об'єкт похідного класу через вказівник на базовий клас, і деструктор не віртуальний — викличеться ТІЛЬКИ деструктор базового класу. Станеться витік пам'яті. Віртуальний деструктор гарантує, що спочатку викличеться деструктор похідного, а потім базового.

💻 Як пояснювати свій код

class Animal {
public:
    // 1. Пояснення: "Це віртуальна функція. 
    // Я дозволяю її перевизначати в дочірніх класах."
    virtual void speak() { cout << "Some sound"; }
    
    // Обов'язковий віртуальний деструктор
    virtual ~Animal() {} 
};

class Dog : public Animal {
public:
    // 2. Пояснення: "Тут я перевизначаю метод. Слово override 
    // допомагає компілятору перевірити, чи дійсно є такий метод у базовому класі."
    void speak() override { cout << "Woof!"; }
};

// 3. Пояснення поліморфізму в main:
// Animal* ptr = new Dog();
// ptr->speak(); // Виведе "Woof!", бо функція virtual

Успадкування і поліморфізм C#

🎙️ Як почати відповідь

"У C# класи підтримують одиничне успадкування через двокрапку :. Поліморфізм реалізується за допомогою віртуальних методів. Для цього в базовому класі метод позначається ключовим словом virtual, а в похідному — обов'язково override."

🎯 Часті питання викладача

1. У чому різниця між `override` та `new` при приховуванні методів?
override: Повноцінний поліморфізм. Якщо ми викличемо метод через вказівник базового класу, виконається метод дочірнього.
new: Просто приховування. Метод відв'язується від віртуального ланцюга. Якщо викликати через вказівник базового класу — виконається метод базового, а не дочірнього.
2. Як у C# викликати конструктор базового класу?
За допомогою ключового слова base(). (У C++ ми використовували ім'я базового класу в списку ініціалізації).
3. Що робить ключове слово `sealed`?
Воно забороняє подальше успадкування від цього класу (аналог final у C++).

Множинне успадкування та Ромб смерті C++

🎙️ Як почати відповідь (База)

"Множинне успадкування — це коли клас успадковує властивості та методи від двох або більше базових класів одночасно. Це дозволяє створювати складні комбіновані об'єкти (наприклад, клас 'Смартфон' може успадковувати класи 'Телефон' і 'Камера')."

🎯 Часті питання викладача

1. Що таке «Ромбоподібне успадкування» (Diamond of Death)?
Це проблема, яка виникає, коли класи B і C успадковують базовий клас A, а клас D успадковує і B, і C. В результаті об'єкт класу D міститиме дві окремі копії полів класу A. Це викликає неоднозначність (компілятор не знає, до якої копії звертатися) та перевитрату пам'яті.
2. Як вирішити проблему ромба?
За допомогою віртуального успадкування (ключове слово virtual при успадкуванні: class B : virtual public A). Тоді компілятор гарантує, що спільний базовий клас A буде існувати в об'єкті D лише в одному екземплярі.
3. В якому порядку викликаються конструктори при множинному успадкуванні?
Спочатку викликаються конструктори базових класів у тому порядку, в якому вони перелічені в списку успадкування (зліва направо). Потім конструктори полів самого класу, і наприкінці — тіло конструктора похідного класу. Деструктори викликаються у зворотному порядку.

💻 Як пояснювати свій код

class Device {
public: int power;
};

// 1. Пояснення: "Я використовую virtual public, щоб при 
// створенні MultifunctionPrinter клас Device не дублювався."
class Printer : virtual public Device {};
class Scanner : virtual public Device {};

// 2. Пояснення: "Тут множинне успадкування. 
// Завдяки віртуальному успадкуванню вище, тут лише одна змінна power."
class MultifunctionPrinter : public Printer, public Scanner {
public:
    void printPower() {
        // Якби не було virtual, компілятор видав би помилку 
        // "ambiguous access of 'power'" (неоднозначність)
        cout << power; 
    }
};

Інтерфейси (Множинне успадкування) C#

🎙️ Як почати відповідь

"Мова C# не підтримує множинне успадкування класів для уникнення 'проблеми ромба' (Diamond of Death). Замість цього використовується множинна реалізація Інтерфейсів."

🎯 Часті питання викладача

1. Що таке Інтерфейс (Interface)?
Інтерфейс (interface) — це строгий контракт. Він містить лише сигнатури методів, властивостей або подій без їхньої реалізації (хоча з C# 8.0 додали дефолтні реалізації, але на лабах зазвичай питають класичне визначення). У ньому не можна оголошувати поля зі станом.
2. Чому інтерфейси вирішують проблему ромба?
Тому що інтерфейс не містить даних (полів) і реалізації. Якщо клас успадковує два інтерфейси з однаковим методом `Print()`, компілятору не потрібно думати, яку саме реалізацію обрати (як це було б з класами), адже клас зобов'язаний сам написати єдину реалізацію цього методу.

💻 Як пояснювати свій код

// 1. Пояснення: "Я створив два інтерфейси. За конвенцією C# їхні імена починаються з літери 'I'."
interface IPrinter { void Print(); }
interface IScanner { void Scan(); }

// 2. Пояснення: "Клас MultifunctionDevice не може успадковувати 
// два базові класи, але може реалізувати скільки завгодно інтерфейсів."
class MultifunctionDevice : IPrinter, IScanner {
    // 3. Пояснення: "Я зобов'язаний реалізувати методи обох інтерфейсів,
    // інакше компілятор видасть помилку."
    public void Print() { Console.WriteLine("Printing..."); }
    public void Scan() { Console.WriteLine("Scanning..."); }
}
